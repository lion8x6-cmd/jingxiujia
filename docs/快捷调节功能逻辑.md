## 一、功能概述

"快捷调节"是 compare 页面三种编辑模式之一（与"局部编辑""一句话改图"并列），通过**预设部位 + 双向滑块**的方式让用户快速调节人像各部位（瘦脸、大眼、瘦腿等）。

核心机制：把滑块数值（-100 ~ +100）翻译成标准化中文提示词，连同整张参考图发给豆包 Seedream 5.0 Pro 模型，由模型重新生成图片。

| 特性 | 说明 |
|------|------|
| 交互方式 | 横向 chip 选部位 + 双向滑块调强度 |
| 调节范围 | 8 个预设部位，每部位 -100 ~ +100 |
| 作用范围 | **全图重新生成**（非局部，无 bbox 坐标） |
| 底层接口 | 豆包 ARK `/images/generations`，图生图模式 |
| 多部位 | 支持同时调节多个部位，一起提交 |

```
|←──────────────●──────────────→|
```

### 5.3 交互逻辑

- **拖动**（`onTouchMove`）：实时计算滑块位置 → 映射到 -100~+100 → 触发 `change` 事件
  ```js
  const percent = deltaX / rect.width;              // 0~1
  let newValue = Math.round(min + percent * range); // -100~+100
  if (Math.abs(newValue) < 3) newValue = 0;         // ±3 内吸附到 0
  ```
- **松手**（`onTouchEnd`）：触发 `afterchange` 事件
- **点击轨道**（`onTrackTap`）：直接跳到点击位置，同时触发 `change` + `afterchange`，±5 内吸附到 0

### 5.4 事件

| 事件名 | 触发时机 | 回调参数 |
|--------|----------|----------|
| `change` | 拖动过程中实时触发 | `{ value: Number }` |
| `afterchange` | 松手 / 点击轨道时触发 | `{ value: Number }` |

```js
recomputeCanSubmit() {
  let can = false;
  if (this.data.adjustMode === 'ai') {
    can = !!(this.data.aiPrompt || '').trim();
  } else if (this.data.adjustMode === 'local') {
    can = this.data.localRegions.length > 0
      && this.data.localRegions.some(r => (r.prompt || '').trim());
```

### 7.3 数值翻译函数

来源：`utils/ai-service.js` 第 165 行 `buildAdjustPrompt()`

```js
function buildAdjustPrompt(adjustments, basePrompt) {
  const parts = [BASE_RETOUCH_PROMPT];               // 1. 通用精修基底
  if (basePrompt && basePrompt !== 'body_adjust') {
    parts.push(basePrompt);                          // 2. 模板自带提示词（如有）
  }

  Object.entries(adjustments || {}).forEach(([key, value]) => {
    const map = PART_PROMPT_MAP[key];
    if (!map || value === 0) return;                 // 跳过未知部位和 0 值

    // 强度分三档
    const intensity = Math.min(100, Math.abs(value));
    const degree = intensity > 66 ? '明显'           // |值| > 66
                 : intensity > 33 ? '适度'           // 34 ~ 66
                 : '轻微';                            // 1 ~ 33

    // 正值→positive，负值→negative
    const desc = value > 0 ? map.positive : map.negative;
    parts.push(`${map.name}：${degree}${desc}`);
  });

  parts.push('整体自然协调，避免过度修饰，保持照片真实感'); // 结尾约束
  return parts.join('；');
}
```

### 7.4 强度档位映射

| 数值绝对值 | 程度词 | 例子（face, value=30） |
|-----------|--------|----------------------|
| 1 ~ 33 | 轻微 | `脸部：轻微脸部轮廓自然收窄，线条流畅` |
| 34 ~ 66 | 适度 | `脸部：适度脸部轮廓自然收窄，线条流畅` |
| 67 ~ 100 | 明显 | `脸部：明显脸部轮廓自然收窄，线条流畅` |
| 0（或不存在） | 跳过，不加入 prompt | — |

### 7.5 完整示例

输入：
```js
adjustments = { face: 30, eyes: -20, leg: 70 }
```

输出 prompt：

逐段拆解：

1. `专业人像精修...细节丰富` — BASE_RETOUCH_PROMPT 基底
2. `脸部：适度脸部轮廓自然收窄，线条流畅` — face=30（34~66 档→"适度"，正值→positive）
3. `眼睛：轻微眼睛大小自然收敛` — eyes=-20（≤33 档→"轻微"，负值→negative）
4. `腿部：明显腿部修长纤细，比例自然` — leg=70（>66 档→"明显"，正值→positive）
5. `整体自然协调...保持照片真实感` — 结尾约束

## 十、与其他两种模式的对比

| | 局部编辑 | 快捷调节 | 一句话改图 |
|---|---|---|---|
| **改哪里** | 手指框选，bbox 坐标 | 不指定，模型自己找部位 | 不指定，模型自由发挥 |
| **改什么** | 用户自由输入文字 | 8 个预设部位，正/反固定描述 | 用户输入任意自然语言 |
| **改多少** | 文字自行描述 | 滑块 -100~+100，映射三档程度 | 文字自行描述 |
| **prompt 格式** | `<bbox>` 标签 + 区域外不变约束 | 部位中文描述拼接，无坐标 | 纯自然语言 |
| **作用范围** | 仅框选区域 | 全图重新生成 | 全图重新生成 |
| **底层机制** | 交互编辑（interactive editing） | 图生图（image-to-image） | 图生图（image-to-image） |
| **模板词拼接** | 不拼接（避免冲突） | 拼接 BASE_RETOUCH_PROMPT + tplPrompt | tplPrompt 作为风格基底 |
| **可控性** | 最高（精确到像素区域） | 中（部位+强度，但模型自由解释） | 低（纯语义驱动） |
| **适合场景** | 去皱、去痘、换局部物件 | 快速瘦脸大眼瘦腿 | 整体风格、氛围调整 |

## 十一、已知局限与注意事项

1. **全图重绘**：快捷调节本质是图生图，模型会重新生成整张图，调节瘦脸时可能顺带改变背景、光影、肤色。prompt 末尾的"整体自然协调，避免过度修饰"只是软约束，不能完全防止溢出。

2. **部位识别依赖模型**：代码不做人脸关键点检测，不指定五官坐标。模型根据"脸部""眼睛"等语义自行在图中定位，多人合照或侧脸场景可能识别不准。

3. **三档程度较粗**：-100~+100 的连续值只映射为"轻微/适度/明显"三档，滑块拖到 35 和 65 效果都是"适度"，粒度有限。

4. **多部位叠加无优先级**：同时调节 8 个部位时，所有描述平铺拼接，没有权重或主次之分，模型可能顾此失彼。

5. **负值方向描述有限**：每个部位的 negative 文案是固定的（如 eyes 的 negative 是"眼睛大小自然收敛"），不能表达更细的反向需求（如"眼睛变小但要保持有神"）。

6. **无实时预览**：滑块拖动只更新数值，不调用模型，必须点"提交修改并生成"等待结果，单次耗时约 10–30 秒。

7. **参考图为最新版**：每次提交都在上一版精修结果上继续调（非原图），多次调节可能累积画质损失或特征漂移，可通过版本历史回退。

8. **`basePrompt !== 'body_adjust'`**：`buildAdjustPrompt` 中有个特殊判断，如果模板 prompt 恰好是字符串 `'body_adjust'` 则不拼接，这是历史遗留的模板 ID 兼容逻辑。
